# 核心词提炼、用户定稿与语义动画

实际口播剪辑先执行 [总规则](../../video-editing-playbook/SKILL.md) 的 SRT 与时间基准检查。本参考统一管理选词、核心词确认、效果选择和反馈学习；[语义字幕](semantic-large-captions.md)、[人后核心大字](large-type-and-occlusion.md) 继续分别管理各自样式，[自动分镜](../../sancheng-broll-animation/references/automatic-direction.md) 管理内容与人物布局。

## 制作前：agent 提案，用户最终确定

每次实际口播剪辑，先读取 [已确认选词偏好](keyword-emphasis-preferences.md)，通读本次授权范围的口播，再提交本次核心词清单让用户定稿。完整包装覆盖全片的重点，局部请求只处理相关范围；用户无需从空白开始逐句标注。此处确认的是核心词及其表达重点，具体高亮、动画、分镜和全屏/画中画由 agent 提出建议并在定稿后自主实现，不增加逐镜效果审批。

完整包装或解释画面先按 [含义、故事难点与痛点深挖](../../sancheng-broll-animation/references/automatic-direction.md#提案前先深挖含义故事难点与痛点) 完成内容分析。清单先简述全片表达主线与最值得解释的难点/痛点，再列核心词及动画建议；重点段说明原文依据、观众可能卡在哪里、拟用什么主体与动作显露障碍及变化。提炼可以超出原文词面，事实和含义仍受原文约束；不把整段分析退化为逐词摘抄，也不把待证推断当事实。全部并入同一次内容确认，不另开“痛点确认”或逐镜效果审批。

清单放在对话中，按语义段汇总，包含：编号、已核实的 SRT/项目时间与原句、建议核心词/短语、为何强调、建议处理。建议处理明确区分普通字幕/人物留白、局部高亮、独立重点字、文字关系动画、解释性 B-roll 或真实资料引导；有歧义时给出候选及差别。暂未核实映射时只标 SRT 时间，不冒充成片精确秒数。没有适合额外强调的内容时明确建议“不设额外核心词”及理由，仍由用户确定。

完整口播包装或授权范围包含开头的补画面任务，将开头手绘建议与核心词放在同一版清单中，依据 [短透明手绘规则](../../video-editing-playbook/references/short-transparent-handdrawn.md) 写明：对应原句和建议时间窗口、要解释的一个含义、画什么及关键动作、预计 2～5 秒时长和透明叠加位置。时间尚未完成项目映射时注明为 SRT 建议窗口；布局是可随实际画面调整的方案。开头不适合手绘时，一并说明原因和更合适的处理。清单确认前只提出文字建议，具体预演与制作在确认后进行；局部任务不扩展为开头重做。

用一次集中提问说明“请确认这版核心词及开头手绘建议，可按编号保留、删除、替换或补充；确认后我会自动完成后续剪辑”，并说明这是用户设定的一次集中确认流程；不涉及开头时按实际清单表述。用户确认后，agent 自主完成技术选型、具体分镜与效果、视觉参考、制作、UISFX、同步和交付检查，继续到授权范围的正式交付；例行构图调整、秒数微调、透明格式和效果优化无需另行确认。收到明确确认前，保持待确认，不制作相关文字、动画、预演或正式包装，也不修改编辑器；可继续核读原文、核对时间映射等不依赖选词的只读准备。沉默、超时、历史喜好及单纯“帮我剪辑”均不代替对本版清单的确认。

用户可直接确认整版，或说明“第 2 条改为……，其他按建议”；按其明确覆盖范围定稿。仅回复某条的修改而其余条目未定时，保留其他条目的待确认状态。用户已在当前任务给出最终清单或确认同一版内容时直接复用，不重复索要确认；变更核心词、强调含义或新增重点只提交受影响项。新视频重新提案；只改时间映射而文案与含义未变时核实新落点，不重开选词。用户当次明确改为无需确认时按当次要求执行，不擅自取消长期默认。

仅调音、裁切、精确字幕纠错等不涉及重新选词的请求，说明本次不改核心词，沿用适用定稿，不扩展成选词或动画任务；规则维护、方法讨论、独立素材及独立 SRT 纠错不触发本流程。确认记录纳入现有制作计划，保留对应原文/SRT 版本、清单版本、用户答复及最终结果；不另建装配 schema。

## 选词：从整段判断到准确短语

1. **确定表达任务。** 先概括本段让观众理解或记住的判断，再识别问题、原因、操作、对比、结果和态度。字幕条目只定位时间，按完整语义合并/拆分，不机械一条字幕配一个词。
2. **找信息增量。** 优先选择改变认识的判断、决定结果的动作、前后差异、必要的否定/条件、关键数字及单位、有情绪重量的短语。“AI、工具、效率”等主题名词只有承载本段独特信息时才强调，不按词频、行业词表或口头重音单独决定重点。
3. **提炼最短的准确表达。** 普通花字常可为 2—8 字，人后核心大字服从其专属字数与样式；字数是设计起点。保留否定、条件、程度、比较对象、数字单位和事实确定性，精确名称与用户指定原文保持准确。提炼只用于包装，不改原口播/SRT；概括性标签标明为提炼，不能伪装成逐字原话。
4. **建立主次。** 每个短语义段先确定主强调点，需要时安排对比或递进的次重点。让普通字幕承载全文、重点字突出判断、B-roll 解释过程，避免同一句多层重复及多个焦点同时抢眼；不设每句、每分钟或全片数量配额。

选词完成条件：候选有原句依据、能说清强调价值、压缩后含义准确，清单覆盖授权范围内的关键论证，并已获得用户对本版的明确最终确认。用户指定的核心词若删掉必要否定/条件或改变事实含义，指出与原句的差异并提交准确候选供其重新确定，不默改定稿或把错误当作偏好学习。明确建议静态、普通字幕或人物表达也是有效判断。

## 效果：按观众需要理解的关系选择

名词帮助确定对象，动词帮助确定动作，关系词帮助组织结构，语气帮助确定强度；结合整句及上下文使用，不建立某个词固定触发某种特效的映射。

| 理解任务 | 优先考虑的表达 | 动作完成条件 |
| --- | --- | --- |
| 记住判断、态度或警示 | 局部高亮、稳定重点字、人物表情 | 准确短语清楚停留，否定与限制同样醒目；没有动态解释收益时静态即可 |
| 看清先后、转折、递进或对比 | 分组补入、位置/层级关系、同参照前后揭示 | 原有信息按需保留，顺序和对比对象清楚；不把先后出现直接画成因果 |
| 理解保留、重做、积累、替换、分发、筛选或核对 | 对象连续的二维/三维解释性 B-roll | 起态→可见动作→结果态可追踪；筛选有依据，积累能继承，替换有接替，分发有来源/去向，核对有检查过程 |
| 看真实软件操作、数字或能力证据 | 原始录屏/截图、局部放大、焦点与关联提示 | 关键操作/数值保留证据与上下文，示意动画不充当真实成功执行或增长证据 |
| 感受亲身经历、情绪或建立信任 | 人物主导、克制重点字与留白 | 表情及语气可感知，文字和动作不抢走叙述重点 |

例如，“上一轮修改保留，下一轮接着做”可提案“保留修改／接着做”，对象在前一轮成果上继续变化；“每次从零开始”则需看见重置和重复劳动。它们是方法示例，未经用户逐词选择，不写成已确认偏好。具体运动读取 [动效选择与实现](../../video-editing-playbook/references/motion-design-vocabulary.md)，布局读取自动分镜规则；核心词确认后照常自主使用全屏 B-roll、同步人物窗口或人物主导。

效果先安排结果阅读态，再反推注意引导、主体动作、落稳和退出，全部放入已锁定的口播窗口。精细重音用实际音频或有效词级证据校准，句级 SRT 不按字数均分冒充逐词同步；UISFX 根据实际动作与语气选声或留白，不逐词响一次。

## 检查：选词准确和效果成立分别核对

| 检查项 | 通过依据 | 差效果或错误的表现与处理 |
| --- | --- | --- |
| 定稿与范围 | 使用当前 SRT 对应的用户最终清单；无新增未确认重点 | 候选被当成定稿、已删词仍上屏、局部请求扩为全片；回到当前定稿及授权范围 |
| 信息价值与覆盖 | 突出本段独特判断/动作/关系，关键论证有明确处理 | 全是泛词、漏掉真正转折，或每句同强度；重排主次，不补特效凑数量 |
| 语义与事实 | 删除/压缩前后判断一致，否定、条件、程度、单位和来源保留 | “不保证”变“保证”、目标变成果、示意变证据；修正后才制作，用户确认不能替代事实检查 |
| 动态解释收益 | 动作让过程、关系、变化或注意顺序更容易理解；适用难点/痛点在主体、作用点和变化中可见 | 只摘原词做放大、换成任意标题也成立、讲筛选只弹卡片；回到故事难点补必要作用过程，静态足够时减少运动 |
| 对象与因果 | 来源、身份、作用点、交接及结果可追踪 | 无故瞬移/复制、发光盒子直接吐成品、积累每镜清空；先修对象关系及中间变化 |
| 主次与可读 | 常见手机尺度正常播放可读，重点与人物/证据合理分配空间 | 字小、遮住否定、重复叠字、多焦点抢眼；先调构图和信息量，再调字号与细节 |
| 时序与声音 | 当前语义落点有效，结果有阅读时间，音效峰与动作/重音相符 | 话完才动、刚形成就切走、尾音盖下一句；在当前口播窗口内减信息或改分镜并校准 |
| 画面与连续性 | 当前正式合成版本的字体、边界、运动、遮挡及衔接已观察 | 只看代码/孤立层/静帧便声称动态通过；按既有局部检查查看同版合成和相关连续区间 |

提案前做选词与语义检查；正式输出时对照用户定稿复查实际内容，并按 [制作检查](../../video-editing-playbook/references/production-checks.md) 和 [B-roll 质量标准](../../video-editing-playbook/references/visual-quality-and-preflight.md) 完成适用观察，证据写入现有计划/内容检查。修正顺序为选词与含义→对象关系→构图主次→动作时序→图形细节与声音；未解决项保持 `issues`，必需观察缺失保持 `unavailable`。沿用既有两轮返修与交付核对，不增独立评分、审批片或运行时字段。

## 学习：把用户的最终选择写回 skill

用户确认、删改或补充核心词后，对照 agent 提案与用户终稿，保存真实的保留/删除/替换/分组差异及用户明确给出的理由；无需用户另说“记住”。本片完整清单和原始反馈留在任务计划，供实施与核对；在 [已确认选词偏好](keyword-emphasis-preferences.md) 写入有原文依据的代表性差异、来源定位、适用情形、迁移结论及生效范围，让下次提案前能读取。

区分“本片定稿”“可复用偏好”“待验证推断”：单次取舍默认只约束本片，迁移推断标明待验证；用户明确说“以后都这样”才将相应范围写为长期规则，反复出现的选择可整理为带依据的候选偏好供后续验证。用户仅确认词语不能推断其认可动画、声音或成片审美；示例、未回复的建议及模型自行解释不能充当用户反馈。重复原则合并为清楚规则并保留必要来源，后续明确纠正更新有效范围，避免累计相互冲突的禁词表。

学习写回是可追溯的 skill 文本更新，不声称模型权重或算法已训练。写后读回并校验受影响 skill 的格式和链接，简述本次学到的差异与适用范围；无法写入时说明失败，不宣称已长期记住。仅维护方法与流程时，记录用户已明确的流程偏好；没有真实选词样本时保留无样本状态，不虚构视频逐词选择。
