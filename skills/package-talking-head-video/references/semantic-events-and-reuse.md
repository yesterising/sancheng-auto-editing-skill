# 语义事件、可复用场景与素材复用

实际剪辑先执行[总规则](../../video-editing-playbook/SKILL.md)的 SRT 确认。本参考负责把当前 SRT、画面动作和复用关系写成可执行的制作计划，沿用现有配方、Blender、人物层与全片装配器。首次包装读完整流程；返修先读旧事件与 build，再处理本次变化。专项技能共用这些关系，不各建一套时间。此增强不要求安装 HYPIT、接入模型或改变剪映宿主。

## 1. 先命名事件，再求当前落点

为需要同步的关键动作命名稳定 `event_id`，例如 `evidence-reveal`、`comparison-result`。ID 表示内容作用，时间或字幕序号变化时仍可保留；相同词句出现多次时，分别定位到实际出现处。不是每个词都建事件，也不把词语映射为固定动作或音效。每个语义段仍有视觉任务；大字字幕可使用静态短语，只有竖屏精选模式可将非重点无字幕留白作为该段任务，横屏完整字幕仍须覆盖全部口播，其余阅读停留、字幕间空隙、片头片尾按总规则承接。

把事件表放在本任务 `work/` 的现有制作计划或独立文件中，记录以下事实；不强制新增一种机器 schema：

| 记录 | 内容与用途 |
| --- | --- |
| 来源 | 当前 SRT 路径与内容哈希；涉及重录/粗剪时同时记录原片、帧率和源时间映射版本 |
| 身份与含义 | `event_id`、所属稳定 `scene_id`、观众应理解的具体变化 |
| 字幕定位 | SRT 块的位置、完整原文或精确引用，以及重复出现时的具体一次；序号独自不能证明仍是同一句 |
| 时间依据 | SRT 句界、用户提供的字词时间、实际观察到的源片动作，或有意设计的片钟时间；明确精度与证据 |
| 当前时间 | 全片绝对帧；持续展示另记 `[start_frame,end_frame)`；固定动画时长与触发时刻分别记录 |
| 消费者 | 哪个场景动作、重点文字、人物布局、素材窗口或声音决策使用它，以及实际对应的参数/代码位置 |

时间仍来自用户 SRT 与获授权的源片时序。可用现有 `sancheng-broll-animation/scripts/srt_timeline.py` 提取字幕边界，传入实际帧率和最终时长；它只提供时间脚手架，不自动决定语义。句级 SRT 只证明句界；引用句内关键词不会自动得到该词的发音时间。需要精细落点时使用已有字词证据或制作范围内的源片局部观察并留证；证据不足就按句界设计、记录精度。不能按字数均分伪造字级时间，也不以此自动转写或替换用户 SRT。

共享边界从同一个有理数时间一次量化为帧，供全部消费者复用；覆盖窗口沿用脚手架的起点向下、终点向上取整，最终仍以工程整数帧为准。SRT 结束可作为窗口开区间边界，不能直接作为该窗口内的最后一个可见/声音帧。事件移出场景或没有足够阅读时间时，重排当前计划并检查覆盖，不能静默截断、挪用旧时间或压缩全部动作。

字幕、视觉动作和声音共享目标事件，各自保留独立职责。声音的 `source_anchor_ms` / `peak_offset_frames` 是音频文件内锚点，保持与全片目标帧的区别。进入 [UISFX 选声](../../koubo-cut/references/uisfx-selection.md)后，仍按实际动作、口播语境和目的选声或留白；事件只决定何时，不决定用什么声音。声音决策可沿用 `event_id` 作 `id`；一个事件有多个决策时保留显式映射及各自覆盖区间。

## 2. 把事件落实到现有制作路径

例如：30 fps，SRT 某句从 14 秒开始，证据场景从 12 秒开始。以该句句首作为 `evidence-reveal` 时，全片目标为 420 帧，场内为 60 帧。重点文字和证据揭示使用同一事件；若 UISFX 判断适合配声，其 `anchor_frame` 也为 420，起音再按实际声音内锚点回推。这只说明换算关系，不提供默认声音、默认场景时长或默认分镜。

`sancheng-scenes/v1` 继续是正式装配合同。事件的依据与含义保留在制作计划中；原生配方现在可按 [已实现事件参数](recipe-production.md) 在场内 `events` 记录全片帧与依据，再由参数引用稳定 ID。它是现有计划的扩展，不另建时间源：

- 场景起止与声效写入现有 `start_frame` / `end_frame`、UISFX `anchor_frame` 和 `prepare` 产物；完整场景连续覆盖全片。竖屏精选大字字幕的留白区间可为透明场景；横屏大字强调层可透明，但须另有完整字幕承载对应口播。
- 配方只使用其已实现参数。步骤使用 `step_events`，汇聚使用 `merge_events`，其他字段查配方目录；不填未实现的 `step_frames`。旧计划可沿用整体入场/均匀推进，但不据此声称字词同步。现有参数不能表达的内部动作，在本任务 `custom-html` 或对应代码中实现并记录消费者。
- 本地页面的 `window.renderAt(t)` 使用场内时间；由全片帧减场景起点得到场内帧，再除实际 fps。动作状态从时间计算，支持直接跳帧，不依赖上一次播放留下的状态。
- Blender、人物窗口、原生 4B 等沿各自现有入口消费相同的全片事件与源时间映射。`custom-html` 仍不承担视频/音频解码；真实人物与录屏沿原路径准备。

制作完成前逐个核对关键事件的消费者：确有渲染参数或代码使用它，正式画面/声音在所声明时刻发生。表中记了事件、但代码仍用另一组旧秒数，不算建立了同步关系。技术检查沿原局部检查流程进行，不增加测试片、全片听审或审批。

## 3. 复用的是场景行为，实例保留本期内容

先按本期语义与画面选择已有配方或项目组件。相对位置、遮罩和动作需要共同变化的对象可由一个场景管理；独立字幕、原声与无关覆盖层保持独立。只把已经存在的重复需要抽成场景，不提前建立万能模板或固定全片结构配额。

可复用场景保留：实现路径与版本、输入文字/真实素材、事件输入、布局及实际字体契约、动作状态与阅读/退出规则。每次使用建立独立 `scene_id` 与本期参数，精确文案、素材身份、事件落点和最终构图归本期实例。先复用当前已实现配方及本地已有组件；新关系需要定制时在本任务 `work/` 制作，只有确有复用需求时才维护共享代码。

例如步骤场景的每步激活有各自事件；人物让位与比较图展开共享空间关系；揭示后答案可停留到后续交接，不随触发词结束立即消失。装饰运动可用本地时长，重要动作不能只按整段的 20%/50%/80% 均分。较长中文、条目数、横竖画幅、真实字重、人物/字幕避让和 Alpha 每次按当前实例检查；换数据不等于自动适配。全片强弱与场景承接仍按总规则设计。

## 4. 明确选择复用材料，并说明失效原因

先查当前工程已有素材、事件计划、正式输出和 build。对本次拟复用项在现有清单/制作记录中登记：稳定资产或场景 ID、原路径、内容哈希、来源及使用权、上次实际检查状态、依赖和本次保留/替换/重算原因。时间相关资产另记尺寸、帧率、时长、原片源入点/速度/映射等适用事实。保留原文件，不复制备份原片，不覆盖旧正式输出或已导入版本。

| 本次变化 | 可保留与必须重算的边界 |
| --- | --- |
| 改标题、颜色或单场布局 | 合适的原片、图片、原声和未变场景可保留；字体、排版及该场依赖按变化重算 |
| 只换一张资料图 | 保留无关素材与事件；图片内容哈希变化使消费它的场景和关联布局/选声判断重新检查 |
| 只改一个声音 | 保留未变画面与声音文件；按新决策重新 `prepare`/`bind`/`check` 并装配全片音轨 |
| 全片字体或共享场景实现改变 | 重新测量所有受影响文字，重做相关场景及依赖；不能把全局修改伪装成单场 patch |
| 重录、SRT 或主片时序改变 | 先锁定新原片与对应 SRT，重新定位事件及源时间映射，传播到所有消费者并重新判断相关声音；可保留适用原始素材和场景源码，不沿用旧秒数或旧声音绑定 |

现有 `scene_pack.py` 的内容缓存、`depends_on` 和 build 记录继续执行，详见[局部迭代](local-iteration.md)。当前实现将 SRT 整体哈希计入画面缓存：SRT 变化会保守失效全场缓存，不承诺自动按词局部重渲染。重录后保留原始图片/场景源码，与复用旧时序的烘焙视频是两回事。缓存命中只证明技术输入一致；复用前仍判断本期的含义、身份、许可和布局是否适用，不把“已渲染”标成“用户已接受”。

历史比较使用旧 build 保存的实际内容指纹，不用旧路径重新读到的新字节代替历史事实。将实际内容/实现/依赖变化交给现有缓存键，不以相同文件名或“之前做过”推断可复用。没有旧 build/哈希时，保留可核实的原材料，保守重做无法证明一致的派生部分；不要为减少重做而跳过检查。

## 5. 本轮完成条件

执行顺序：SRT 确认 → 当前事件与场景/素材选择 → 字体、布局与动作实现 → 每次 UISFX 选声或留白及当前计划绑定检查 → 全片装配 → 正式输出局部内容检查 → 文件技术解码与可用性检查 → 展示并交付文件，由用户自行导入和拖入；返修交新版供用户手动替换。

交付前能回答：关键事件来自哪句、由哪些实际消费者使用；哪些场景/材料复用、哪些失效；当前 UISFX 记录是否覆盖完整计划并检查通过。默认交付仍从 00:00 覆盖全片，辅助层同时间基准，用户最后拖入。事件表、场景实例和缓存留在 `work/`，不把内部拆分转嫁给用户，也不把记录完成报成素材已制作或已导入。
