# 自动选择动画、全屏展示与人物窗口

## 默认执行范围

用户已将这套自主安排设为默认。用户把口播放入当前剪映工程，提供对应 SRT，并要求“按默认流程包装”“补 B-roll 和解释性动画”或同等完整包装任务时，先按 [核心词提案与用户定稿](../../koubo-cut/references/core-keywords-and-semantic-emphasis.md) 确定本次表达重点；之后由 agent 在本次整片或指定范围内决定动画类型、全屏展示区间、人物窗口形状、位置和切换点，直接完成设计与制作。核心词由用户最终确定，分镜、具体效果和常规全屏/画中画切换无需逐镜批准。

用户说“补画面”“加剪辑画面”而未限定具体手法时，在指定区间内同样自主选择适合的精细动画与布局；不能自行缩窄成只在人物两侧加文字卡。用户本次指定的保留段、只处理的区间、仅加字幕/声音、仅叠加或人物常驻等限制优先。自主安排画面不改变口播剪切、文案与原声，不扩大时间线操作、保存/导出或外部付费授权。仅要求解释方法、分镜或独立素材时，完成对应范围。

实际剪辑第一步仍是确认对应 SRT 可读。之后结合全文论证、实际口播画面、人物与字幕位置、既有剪切/变速、必要的语义重音安排。SRT 提供句段时间，不自动提供词级精度；核心词按上文请求用户定稿，时序明显不匹配、必需素材无法读取或工具确实阻塞时再询问具体缺口，其余常规设计判断由 agent 完成。

## 先选内容，再选布局

判断顺序为“观众要理解什么→什么对象发生什么变化→用真实资料/二维/三维还是人物表达→动作与结果需要多少空间→人物位置与展示时长”。数字人或真人在原片中居中，只是输入状态；画中画是内容需要空间时采取的布局，不是使用 B-roll 的前提。人物主导段的脸部保护不反向限制内容主导段。

## 提案前先深挖含义、故事难点与痛点

每次完整口播包装或授权段落的解释画面设计，先通读全文，理解这一段在整个故事中的作用，再提炼核心词和选动画。先在现有计划中形成简明的内容判断：本片的主张与论证如何展开，涉及哪些主体和目标，观众当前可能怎样理解，看完应理解什么；结合故事追问困难发生在哪一步、谁承担什么成本或风险、哪项条件阻碍结果、前后真正改变了什么。按本片适用内容分析，不为每段硬套商业、痛点或冲突模型；没有障碍的定义、事实与情绪段，直接辨明理解难点或表达任务。

将原文事实、跨句归纳、解释性隐喻和待证推断分清。含义可以由多句共同支持，不限于原文出现过的词；归纳短语注明为提炼，镜头指向对应原句。故事没有说的动机、因果、金额、痛苦程度和结果不补成事实；需要新事实支持的推断保持待证，不用画面提前坐实。沿全文保留否定、条件、代价与反例，避免把“有需求”画成“一定成交”、个案成功画成普遍收益，或把受多项条件影响的结果简化成单一原因。

对有解释收益的重点，把分析变成具体场景：原来的处境或障碍是什么，哪个主体带着什么对象采取什么动作，动作在何处发生作用，最后什么关系或状态改变，以及观众因此理解了什么。先选最能显露难点的动作，再决定手绘、真实资料、二维/三维或人物表达。关键词承担标签与记忆提示；仅放大名词、让卡片入场或给任意收入段套同一个增长动作，不能替代这一场景设计。静态或表情已足够清楚时保留它，不为“深挖”强加动画。

例如，口播同时谈到制作成本、播放表现与平台补贴时，挖掘的是投入先发生、回本受哪些条件影响；可让持续发生的制作支出与变化的激励来源形成可追踪关系，具体结果沿原文，不虚构亏损数字。口播讲人工表格与定制系统时，可让同一批记录经历反复核对、再被对应功能处理，显露劳动发生在哪里、交付解决了什么；不能凭一个系统图标就跳到现金到账。这些是推理方法示例，不能固定成其他视频的模板或用户已验收镜头。

提案阶段只做文字分析与分镜建议，把主线、关键难点/痛点及开头建议并入既有核心词清单，仍只进行一次集中内容确认。确认后自主完成具体设计、蒙版与制作。原片只有人物口播时，结合实际帧标注人物/手势、字幕、介绍和动画区，按理解需要采用人像蒙版、分区、同步人物窗口或内容全屏；蒙版和布局是实现手段，不代替故事分析，也不要求用户先框位置。具体时长、工具分流与透明标准继续沿下文及总规则。

## 哪些内容需要动画

先通读授权范围内的论证与情绪，而非逐条字幕配一个效果。判断动画能否让观众更容易看出过程、关系、变化或重点；有明确收益且可实现的关键段，应实际制作完整动作。先按下文短透明手绘规则识别逐笔分支，其余适配动画优先选择 Lemo 风格、技法与有效素材。已有清楚的真实镜头或动画能完成任务时可复用，不为调用工具重复制作。

| 适用语义 | 动画应该让观众看到什么 | 选材与边界 |
| --- | --- | --- |
| 流程、分工、任务交接 | 同一对象从来源进入不同角色，发生处理，再到下一步 | 展示输入、处理、交接、输出；并行或串行由真实逻辑决定 |
| 原因、机制、故障与修复 | 某个动作如何导致状态变化，哪里出错、怎样修正 | 展示作用点和变化过程，避免只在两个标题间切换；示意不充当真实软件运行证据 |
| 积累、迭代、规模或时间变化 | 前一步如何被继承、扩展或重做，结果怎样形成 | 同一对象和参照保持连续；数字、比例与增长口径有依据，不用虚构计数增强戏剧性 |
| 方案比较、前后差异、取舍 | 相同参照下的关键差异、代价与变化方向 | 有变化过程才动画揭示；静态并列已足够清楚时保留阅读，不强加运动 |
| 信息筛选、分类、结构与层级 | 候选按什么依据被保留/排除，信息如何组合 | 筛选依据来自口播，分组/路径可追踪，不只是卡片弹入 |
| 抽象观点、故事转折、结果揭示 | 具体物体或场景中的冲突、行动与可识别结果 | 可用二维/三维隐喻；映射清楚并与上下文一致，不机械遇到抽象名词就放机器人或积木 |
| 软件操作、证据与数据细节 | 原始操作步骤、鼠标焦点、局部变化与结果 | 真实录屏/截图主导，动画只做引导、放大、关联和必要解释；不重绘出并未发生的成功操作 |

态度、情绪、亲身经历及需要表情建立信任的段落优先人物主导；简单结论可用重点文字或稳定资料。核心是内容收益，精细二维同样可以成立；不设全片动画占比、每分钟次数、固定片长或全程三维要求。对适合但未采用动画的重点，在原计划简记实际原因（已有有效素材、证据应原样展示、当前段落时长或实现缺口），不能仅写“人物居中”“用户没说画中画”或“加过一张图”。

## 短视频中的短手绘插入

完整包装或授权区间补画面时，执行剪辑总规则的 [短视频透明手绘](../../video-editing-playbook/references/short-transparent-handdrawn.md)，自主完成选段、制作与同步。该参考统一维护开头优先、短时长、透明背景与物体白色保护，以及 Nikola/Lemo/真实素材的选择；本页不重复维护一套参数。

## 再分配画面与人物

动画是内容形式，全屏展示是内容占比，圆窗/方窗是人物呈现方式；可以组合，例如“全屏机制动画＋同步口播小窗”。需要完整观察过程时，也可暂时只显示内容，原口播声音持续，讲到个人判断或结论时恢复人物；本次明确要求人物常驻时保留同步窗口并重排内容。

| 语义与观看需要 | 默认内容选择 | 人物与布局选择 |
| --- | --- | --- |
| 流程、因果、输入输出或机械动作，动态解释有收益 | 先按内容选择 Lemo 的二维排版、路径/结构动画或真实三维；物理过程适合积木/机械时才采用，复杂动作再走 Blender | 内容铺满主要画面，需要人物时用同步小窗；完整过程需要全部空间时可暂时只显示内容 |
| 软件步骤、功能证据、真实案例、长截图、图表或细小文字 | 优先真实截图、录屏与原始资料，局部放大讲解 | 内容全屏或占主要区域，人物缩成圆形小窗，避开数据、按钮、鼠标与字幕 |
| 解释少量概念，同时需要保留表情与手势 | 相关资料或动作图示与人物分区 | 方形/圆角矩形画中画，保留更多上半身，按实际留白决定大小与位置 |
| 观点、态度、情绪、个人经历或结论 | 人物主导，配与当前含义有关的重点强调或资料关联 | 保持或恢复人物较大画面，表情、手势与字幕可读 |
| 完整场景、加工过程或结果需要更多观察空间 | 让对应资料或二维/三维场景全屏展示并保留阅读态 | 自主决定无人物全屏或不遮挡的同步小窗，原声持续；明确人物常驻的要求优先 |

积木只在能帮助理解时采用，不把真实产品界面、具体数据或证据换成虚构积木画面，也不强制每段都出人物动画。圆窗不固定右下角；方窗保留更多手势，小圆窗节约阅读空间，窗口形状由当前观看需要决定。若常见位置都遮挡内容，重排信息与人物区域，不缩小资料到不可读。

## 动作与切换怎么落在口播上

先按问题、原因、操作、比较、结果和结论组织语义段，再在已有场景计划记录：源字幕/原文、工程起止、理解目标、对象起止态、关键动作与结果、内容形式、人物模式及布局理由、阅读与承接、声音锚点及实现路径。记录反映已做的判断，不另增装配 schema；计划是 agent 的制作依据，不把填表、逐场选效果或找音效的工作交回用户。

在完整观点、操作步骤或场景交界处切换，不按固定秒数、字幕条数或配额轮换。铺满画面用于需要观察过程/细节的段落；结果落稳后留出阅读时间，进入态度或结论时恢复人物主导。动作高点对齐实际接触、结果揭示或语义重音，窗口切换期间声音连续。

例如“以前在多个工具之间切换，现在一个工作流串起来”：先全屏展示分散模块与同一份素材的来回移动，人物进入小窗；讲到连接时，模块接通、素材顺序通过；结果落稳；下一段讲个人判断时恢复人物较大画面。积木适合示意机制，真实工具能力的证据用真实界面承接。

## 实现与交付

实际制作先按 [视觉完成度与代表镜头预演](../../video-editing-playbook/references/visual-quality-and-preflight.md) 的 B-roll 质量判断，验证该镜头的语义、因果、可追踪性、动作和阅读态，再扩展或复用；仅有“动画能播放”“已有大字/粒子”不算完成精细动画。预演、正式文件复查与有限返修沿用同一流程，不新增逐镜审批。

积木制作先按 [Lemo 优先规则](../../video-editing-playbook/references/lemo-opuscar.md) 选择适用的真实三维实现；复杂骨骼、接触或机械动作更适合时按 [Blender 流程](blender-workflow.md)。人物裁切、真实蒙版、源时间映射与内容覆盖按 [画中画执行](layouts-and-pip.md)。全屏内容需覆盖原来的大人物，需要保留人物时再将同期窗口放在上层；普通透明叠加不会自动缩小底片。所有窗口沿最终口播源时序同步，新层静音，原声只保留一份。

agent 提前装配动画、布局变化和音效：主包装与必要辅助层从 00:00 起，同全片时长、画幅和帧率。完整包装的各语义段持续承接，人物主导段也有相关视觉任务。最后按总规则检查正式文件可用性并展示、链接，由用户自己导入素材库并从 00:00 按必要层级拖入；AI 默认不导入、不建轨、不替换。
