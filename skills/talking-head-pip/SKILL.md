# 口播画中画

将同一份口播画面按内容需要放入圆形小窗、圆角矩形大窗或多个同步窗口。用户描述效果即可自动调用，首次采用时简短告知用途并继续；资料齐全时直接执行已授权工作。

执行剪辑的第一动作是按 [视频剪辑总规则](../video-editing-playbook/SKILL.md) 确认用户已提供当前 SRT，缺失立即提醒并停止其他制作。默认由 Codex 处理已放入剪映的当前视频，三橙剪辑台仅在明确指定时使用；完成条件与用户手动导入分工以总规则及当前指令为准。只问“怎么做”时给出实现解释；要求制作时完成正式素材与同步准备。普通口播包装只有实际需要画中画时才采用本技能。

## 自动选择布局

判断依据是观众是否需要阅读或观察细节，而非元素数量。先看当前内容、字幕和界面遮挡区域，再选布局；在完整观点、演示步骤或场景交界处切换。

| 模式 | 触发条件 | 人物与内容安排 |
| --- | --- | --- |
| `circle-small` | 长截图、图表、表格、流程、软件操作，或任何需要读小字的画面 | 内容主导；口播人默认在右下角圆形小窗，保留头部和少量肩部 |
| `rect-large` | 标题、关键词、简单图片、观点总结，且存在足够留白 | 口播人用大圆角矩形窗口，保留上半身与手势；人物和文字分区，默认人物左、信息右 |
| `multi-window` | 用户明确要多个窗口，或示范画中画、对比、强调动作确实需要多个窗口 | 复用同段口播，分别设置裁切、大小和位置；案例采用左侧大窗加右下角小窗 |

右下角是默认位置，字幕、重点数据、按钮、鼠标演示或平台控件占用时，移到其他空白区域；必要时给内容预留独立的人物区域。单张复杂图仍采用小窗。普通段落默认一个窗口；用户明确要求全程多个时遵从其范围。


## 构图和参数

- 工程尺寸、帧率、最终剪辑时序和已有字幕位置优先。横屏 1920×1080 的小圆直径可从 220–300 px 起步，边距 40–60 px；其他横屏按比例调整。大窗宽度可从画面宽的 50%–65% 起步，根据旁侧内容压缩。竖屏重新布局，给字幕和平台控件留空间，不机械套用横屏坐标。
- 圆内脸居中，头顶有余量；脸部或手势偏离时调整源裁切与窗口内的位置。圆形蒙版保留圆内拍摄背景，需要去背景时才另做人像抠像。
- 圆角大窗按窗口比例裁切，保持人物比例和口型；边框不能代替真实圆角裁切。旋转、描边、阴影只在有助于当前风格时添加。
- 画中画替代原全屏人物位置时，旁侧文字以实际窗口范围避让。其他包装技能的“中央人物保护区”只适用于人物仍居中的场景，不能阻止本任务需要的重排。

## 同步和声音

先完成本次获授权的口播剪切，再以最终时间轴建立各窗口。复用原素材路径和媒体引用；无需复制原片文件。多个窗口同一时刻引用相同源片段、入点、速度和变速映射，源切点也保持一致。用户明确要求对比不同片段时才改变源内容，并区分正在说话的窗口。

全程只保留一份口播声音；原工程已有声音时，新窗口素材默认静音。窗口切换不切断声音。已有烧录字幕随源画面一起缩小，不把小窗中的字幕当作全片主字幕；按本次授权范围沿用或处理主字幕。

## 执行路径与交付

制作前读取 [执行方法](references/execution.md)，选择当前工具环境能够完成的路径。静态蒙版和裁切可使用原生编辑器或 FFmpeg；窗口运动和转场按用户默认读取 `hyperframes-core` 与 `hyperframes-animation`。使用已有工具的实际接口，不能把设想的蒙版 API 或普通矩形叠加当作圆形能力。

默认将全片画中画变化、必要人物层和包装提前完成同步；交付文件统一从 00:00 开始、同全片时长，延迟出场辅助层可透明等待，由主包装承接。按总规则完成文件可用性检查后，在 Codex 展示并链接正式文件，由用户自己导入剪映、放到 00:00 并依必要层级摆放，不逐场找秒数。本流程的导入、放置和替换由用户完成；只有明确要求草稿或成片时才生成相应产物。缺少必需口播或内容素材时说明缺什么，继续不依赖该素材的准备，不生成替身或臆测正式素材。

交付前按当前制作状态核对：布局覆盖本次范围；多个窗口源时序一致；口播音频只有一份；字幕与关键内容已避让；生成叠加素材保留 Alpha；首帧有实际人物或信息；可用性检查与正式文件交付已完成。这些项目纳入总流程正式文件的正式输出改动区间检查；不另起小样、整片验收或重复检查。返修或重做均生成新正式文件，检查后给出新文件链接，用户自己替换；用户导入后不再自动检查。只完成技能安装或布局规划时，报告实际完成项，不称视频已剪好。
