# 画中画执行方法

完整包装默认可自主选择全屏内容与圆窗/方窗，不等于授权新增时间线片段；实际制作先确认 SRT。正式输出交给主流程统一做 正式文件改动区间检查与最多两轮返修，返修交付已检查的新文件供用户手动替换；以下原生操作仍受该范围限制。

本文件承接口播画中画的制作，不重复总流程的导入和授权规则。依照实际工具能力选择以下路径；不为调用更多工具扩大范围。

## 建立时序与布局

先按总规则确认用户提供的当前 SRT，缺失立即提醒并停止，之后才沿用当前剪映工程尺寸、帧率、原片路径和已定稿时序。用 SRT 与屏幕内容按场景分段，不重新转录。需要从源画面定位人脸、手势或内容遮挡时才读取当前环境的 `visual-analysis`；这是制作所需定位，不增加交付验收。

在当前项目的工作目录记录必要的分段信息：每段开始/结束时间、模式、源路径与源入点、速度或变速映射、每个窗口的像素边界、源裁切区域、圆角/圆形参数和音频归属。复杂剪切逐片段映射；直接从原片的同名秒数取画面会在删减后失去同步。简单任务可用紧凑布局表，只有制作工具需要时才生成 JSON。

内部场景在交付前装配，正式主包装与必要辅助层统一从项目时间 00:00 对齐、同全片时长。延迟出场辅助层使用透明区间保持时间位置，主包装始终有内容承接；不交付让用户逐场找起点的片段。窗口之间始终共享同一源时间映射，切换布局只改变展示。

## 原生编辑器路径

以下仅供独立明确的原生技术任务查阅，不属于本用户日常文件交付路径；日常画中画使用下方透明派生素材，由用户导入、拖入和替换。其他宿主的独立任务读取各自适用入口。

复用口播片段到需要的上层视频轨道，保持起点、时长、源入点和速度同步。先调窗口内的人物构图，再设置圆形或圆角矩形蒙版，最后调窗口的大小与位置。多个窗口分别设置展示参数，音频统一静音并沿用主口播轨。边框和阴影随整个窗口移动。

优先使用当前版本可用的原生蒙版/框架功能。调用 API 前读取实际工具说明；没有对应接口时，可在授权范围内使用编辑器界面或生成透明派生素材，不能猜测 `add_circle_mask` 等方法。遵守总流程的原片、保存及导出约束。

默认文件交付走下方派生素材路径；原生时间线操作不作为绕过分工的捷径。

## 透明派生素材路径

适用：默认素材交付，或当前原生工具无法表达需要的布局。静态裁切与蒙版读取 `ffmpeg-skill`；编写项目脚本前读取 `coding-discipline`，脚本放当前项目工作目录。

处理次序：按最终源映射取帧 → 保持比例裁切人物 → 缩放窗口 → 生成窗口形状的 Alpha → 添加需要的边框/阴影 → 放到工程尺寸的透明画布 → 按布局段落串接。多个窗口各自处理后叠到同一个透明画布。圆形遮罩外 Alpha 为 0、内部可见，边缘适当抗锯齿；圆角矩形四角也必须实际透明。圆内的拍摄背景可保留，这与窗口外透明并不冲突。

优先采用当前剪映已可用的透明编码路径，例如 QTRLE MOV/ARGB。容器后缀不能证明 Alpha；以制作中的画布、像素格式和编码配置保证透明，当前路径无法输出时报告实际阻塞。完整包装或指定区间补画面时，按 [自动分镜规则](../../sancheng-broll-animation/references/automatic-direction.md) 自主准备覆盖原大人物的全屏内容层，必要时叠同步窗口，或在该段暂时只显示内容；区间外透明并按语义恢复人物。仅制作人物窗口的任务只渲染窗口和所需新增元素，不扩大为全屏背景或替代底片。

`ffmpeg-skill/scripts/overlay.py` 的现有 `--video` 路径支持普通视频叠加，但自身不能直接提供圆形/圆角裁切，而且输出是与底片合成的视频。仅在明确要求该类合成文件时使用它；默认透明窗口制作应使用具备 Alpha 输出的处理链，不把该工具的普通叠加命令当作完整实现。

透明派生素材是已渲染窗口，能作为视频移动和裁切，但不能声称里面的窗口参数具有剪映原生关键帧可编辑性。可编辑窗口需求按实际可交付文件说明能力，不自动进入当前原生工程路径；明确要求导出可编辑剪映草稿时再读取 `jianying-roughcut-export`。

## 动态布局与切换

读取 `hyperframes-core`、`hyperframes-animation`，并按当前任务读取 core 的媒体时序与 creator-editing-recipes 参考。每个视频实例显式声明源时序和唯一标识，遵循框架拥有的媒体播放与可寻址时间线；同一源的多窗口同帧同步。

人物视频放进可裁切的窗口容器：圆形以等宽高和圆形裁切实现，矩形以真实圆角裁切实现。容器定位决定画布位置，容器内源画面的裁切决定人物构图。父容器与视频的计时属性按 core 合约安排，不给父子同时叠加冲突的计时。

根据语义选择连续运动或直接切换；重点窗口变化设计具体运动与承接。运动可从约 0.2–0.4 秒作为可调整起点，动画改变窗口位置和尺寸，边框/阴影跟随；形状切换用直接切换或短暂透明度交接，只有实际渲染路径支持时才做形状变形。发生交接的两个实例引用同一源时刻且静音，避免错位口型。动作从可见内容开始，全片音频保持连续。

最终交付仍按总流程保留真实 Alpha。HyperFrames 当前渲染路径不能直接保留 Alpha 时，采用能够保留 Alpha 的派生素材路径；不能用黑底 MP4 或绿幕替代透明交付。

## 原人物底片的安排

把原全屏人物缩成窗口时，窗口以外应该显示截图、录屏、图表或所需背景。透明窗口素材叠在原全屏人物上，会同时出现小窗和底下的大人物；单窗口场景需要底层内容覆盖原全屏人物画面。制作时准备好本次获授权的内容层与同步说明；用户自行导入并按说明摆放；本流程不代放置。案例式多窗口只有需要大窗加小窗时才保留两个可见人物。

## 典型请求的落点

- “讲软件时右下角圆圈，讲观点时变大”：软件演示段选小窗；总结段选大窗；保持同一份声音，在步骤边界切换。
- “做成上次图里一大一小的两个人”：读取案例图；同段口播分成大圆角窗和小窗，源时序同步，声音保留一份。
- “图上字很多，圆圈挡住右下角数据”：优先移到其他留白处；无留白时安排人物独立区域，保证数据可读。
- “教我画中画怎么做”：解释多轨、裁切、蒙版和同步，不操作工程。
