# 视觉完成度与代表镜头预演

首次完整包装、新解释动画、风格化 B-roll 或重做视觉方向时，在双站参考研究后、批量制作前执行本参考。局部改字、调音及已验证风格的参数返修只检查受影响项，复用仍适用的设计和预演。规则维护不启动剪辑或索要 SRT；实际剪辑仍先通过总规则的 SRT 门槛。

## 目标：符合三橙 AI 内容的精细科技视觉

用户于 2026-10-30 明确指出：画面不好看、画面效果不足、动画粗糙、缺少精心制作感，与 AI 内容的科技定位不匹配。后续默认面向成熟科技产品演示和科技编辑视频的完成度：信息有主次，真实产品清楚，图形精确，空间与材质统一，动作有编排和细节。具体造型仍由本片内容、原片与实际参考决定；该方向是制作标准，尚不是用户对某种具体画风的审美认可。

科技感通过信息结构、精确图形、真实界面、受控空间和运动建立。配色可明可暗，依据原片、素材和参考确定；EVA 字幕、实际中文字体、大字可读和原始证据继续服从总规则。积木、卡通、全息、玻璃及金属按本期表达选择，均不自动成为全片默认造型。

## 默认可见性要求

用户在“多个 AI 工具协作”精修后明确要求，将画面亮度、主体尺度、工具处理、数据分发和结果汇聚的可见性作为后续默认制作标准。新增及重做视觉须在正常播放、实际发布画幅及常见手机观看尺度下满足以下适用条件；复用素材也要确认当前构图仍满足。具体颜色、三维装置、工具数量、数据包数量和片长由本片决定。

| 项目 | 完成条件与调整方法 |
| --- | --- |
| **画面够亮** | 主体的表面、内部结构及关键动作能直接分辨，暗部有层次，高光保留材质与轮廓。通过适用的背景明度、材质、面光、补光及渲染曝光，让主体与背景分开；暗色风格同样保持动作可辨。透明层须放到实际原片背景上检查。 |
| **主体够大** | 观众无需暂停或放大即可识别核心对象、处理动作和结果。先为主体及动作范围分配版面，再安排标题、人物窗口和装饰；总览交代关系，细节不足时切近景、局部放大或拆分展示，同时保留必要的来源与去向。依据实际可见性定景别，不机械固定占屏比例。 |
| **工具处理看得见** | 清楚呈现“接收什么→如何处理→得到什么”。为关键工具安排可见的对象或状态变化，例如扫描对应被检视/选中的资料，排序对应数据位置或层级变化，生成对应组件组装或内容形成。标题、状态灯及无关转动只作辅助；真实软件处理继续以原录屏/截图为依据，概念动画如实标明。 |
| **数据分发可追踪** | 起点、分流关系、各自去向与接收时刻清楚。按观看尺度安排数据对象的大小、对比、路径间隔和速度，需要时用短尾迹或通道光流辅助追踪；给出从来源发出、沿路径移动、到达并触发接收的连续过程。多路同时呈现过密时分批展开，保持来源身份与方向一致。 |
| **结果汇聚有过程** | 能分辨各路结果从哪里来、怎样移向共同目标、在哪里交接，以及如何组合成最终输出。按内容展示必要的回流、接收、拼合/整合、落稳和结果阅读态；最终结果保留清楚的识别时间。涉及多个来源时让观众可追踪其贡献，声音的接触峰与完成提示对齐实际交接/落稳。 |

工具处理、分发和汇聚只用于本片实际存在的关系，其他题材沿自身语义执行，不为满足清单新增无关工具或流程。亮度调整优先在本次新增视觉的设计与渲染中完成；原片调色及主片时序仍遵守本次授权范围。独立动画按所需动作与阅读安排时长；口播包装沿锁定 SRT 和原片时间，在段内调整信息量、景别及动作节奏。

## 先把参考变成可执行的设计

在已有制作计划或本期 `work/design.md` 中集中记录本次适用的设计决策，避免每个镜头独立选风格：

| 决策 | 必须说清的内容 |
| --- | --- |
| 视觉主张 | 本期画面应传达什么气质，哪些主体和空间关系最能表现这段内容。 |
| 构图与层次 | 主体占据的实际区域、人物与证据如何让位、观众先看什么再看什么；用原片对应帧检验。 |
| 图形与材质 | 形状、线条、圆角、透视、表面细节、光照和阴影采用什么共同规则；二维内容按二维精度制作，不为追求质感强加三维。 |
| 字体与色彩 | 当前锁定的真实中文字体/字重、主辅文字层级、背景与强调色用途，以及总规则字幕样式如何融入版面。 |
| 动作语言 | 关键对象如何入场、变化、落稳、阅读、接续；动作之间的主从、重量、速度和声音落点。 |
| 参考到实现 | 每个采用来源借鉴的具体细节、如何适配横竖画幅与中文、实际实现路径及已知差距。 |

搜索沿用 Pinterest→Cosmos MCP 和实际看图要求。需要对标动画节奏、转场或动作完成度时，补充可实际观看的动态参考；仅有静态图时只借鉴静态设计，动作采用明确的自主设计并在本片预演验证。参考选取以本片能落实的设计细节为依据。

## 镜头要有内容效果和制作细节

依据语义选择画面表达：真实产品展示突出实际操作、局部放大、状态变化和结果；抽象机制将输入、处理、关系和输出变成可追踪的对象；观点与对比用文字尺度、空间关系和结果揭示形成冲击。相同画风下，各镜头按任务变化景别和动作。已有全片覆盖及竖屏精选留白规则继续有效，强弱分配服务于重点。

关键镜头应实现观众在正常播放时能明确感知的视觉变化。按表达可采用超大字与人物的空间关系、真实界面的镜头推进、同一对象跨镜变形、结构展开与重组、具有层次的 2.5D/三维机制演示等；由实际内容选择并制作完整过程。精细制作同时要求重点的可见强度和细节完成度，普通段保持有主次的阅读节奏。

为重点动作落实以下适用细节，写入原事件/场景计划即可：

- **编排：** 先安排结果阅读态，再反推主体动作、注意引导与交接；同屏对象分清主从，次级动作响应主体，避免整组元素只有同一种整体滑入。
- **运动：** 距离、时长、缓动与对象重量相符；有需要时设置短促预备、跟随、减速、接触或轻微回稳。静态停留保持清楚，动作承担信息变化；弹性、运动模糊、视差等按效果选用。
- **空间：** 对象位置、遮挡、透视和身份在变化前后连续；接触动作有接触点，聚合/拆分能追踪来源，人物层与证据使用真实同步素材。
- **画面细节：** 按选定风格处理轮廓、对齐、边缘抗锯齿、图像清晰度、表面和光影；细节在最终发布尺度可见且服务主体。原始截图、Logo、数字及中文精确文字保留原资产。
- **承接：** 当前对象、视角或结构能延续时用其引入下一镜头；需要切断时有明确节奏理由。入场、阅读和退出都纳入实际时长，避免主体刚形成就消失。

通用库中的装饰数量、焦点数量、缓动数量及“每个装饰都持续运动”等建议不是本用户的完成条件。按主体与语义决定密度，稳定且有主次的画面可以成立。先改构图、主体造型和动作关系，再按需要补材质及装饰；效果不足时定位缺少的视觉变化，选择相应实现。

## B-roll 动画怎样判断好坏

先按 [自动分镜规则](../../sancheng-broll-animation/references/automatic-direction.md) 判断本段是否有动态解释收益，再检查实际镜头。精细程度取决于本片对象、动作与结果的完成度；二维或三维、用了什么工具、渲染成功、装饰多少都不直接证明质量。

| 检查角度 | 效果差的可观察表现 | 优先修正 |
| --- | --- | --- |
| 含义与故事难点 | 画面只重复原词，看不出本段特有的障碍、代价、条件或理解关系；只有标签在说“痛点”，对象没有对应行动 | 对照全文与引用，按 [含义深挖](../../sancheng-broll-animation/references/automatic-direction.md#提案前先深挖含义故事难点与痛点) 重选起始处境、作用点与变化；适用时让难点及其处理可见，平实内容保持准确，不硬编冲突 |
| 语义增益 | 标题换成别的话也同样成立，关键过程只靠旁白说明，图形只是装饰 | 先写清本段对象、变化与结果，保留能帮助理解的动作；静态已足够时减少运动 |
| 因果与处理 | 文件进入盒子，盒子发光/旋转后突然出现成品；看不到处理或中间状态 | 展示必要的筛选、重排、组装、检查或作用点，让结果由动作形成 |
| 来源与连续性 | 对象瞬移、无故复制或换身份，多路资料的去向、交接和贡献看不清 | 保留身份线索与路径，明确发送/接收时刻，分批呈现过密信息 |
| 主体与注意顺序 | 中央人物占住核心区域，动画挤在边角；多个元素同时抢眼或关键动作太小 | 为内容扩大空间，选全屏/同步小窗/暂时只显示内容，减少同屏竞争，按需要切近景 |
| 运动与空间 | 不合风格的统一弹跳、匀速漂浮、动作突停，穿模、接触错位、透视或遮挡跳变 | 按材质和风格调整速度曲线、接触与落稳，逐段连续查看；Swiss等精准风格不强加弹性 |
| 时序与阅读 | 话已说完动画才开始；所有对象同时进出；结果刚形成就被切走，必须暂停才能看清 | 按真实语义锚点排引导、动作、阅读、离场；在锁定口播区间内减信息或改分镜，不拉伸原声/SRT |
| 图形与材质 | 字体回退、截字、线宽和对齐不一、低清锯齿、暗部糊成团、材质/光照逐镜漂移 | 用实际中文字体、发布尺寸和原片合成检查，统一造型/线条/材质/灯光；细节应在手机尺度可见 |
| 声音与衔接 | 接触音早于/晚于动作、尾音压住下一句，镜头突换且没有内容承接 | 沿共享事件与UISFX决策修正峰值、增益、尾音和留白，安排同一对象或清楚切点承接 |
| 事实含义 | 概念界面像真实成功录屏，虚构数字/图形暗示未经核验的增长或成果 | 使用原始证据，修正图形含义并标明示意；不以美术效果代替事实依据 |

制作中可做两个简短的自查：保留必要标签，暂不依赖旁白，能否看出主体做了什么、发生什么变化、最终留下什么；再判断若换成只有标题或静态图，是否会丢掉重要过程、关系或注意顺序。它们是帮助定位问题的观察方法，不要求额外渲染对照片，也不把所有段落都变成无文字动画。

按“语义与因果→构图/人物布局→动作时序→图形细节→声音”处理实际问题，避免用更多粒子、发光或加速掩盖过程缺失。复用场景应绑定本期内容、起止态及结果，不照搬与本片无关的模板故事。预演与正式检查各自只用同版有效证据；在正常速度、常见手机尺度、实际口播与所有正式层合成后确认。影响理解或可用性的上述问题记录为 `issues`，修正并复查前保持未通过；未观察的动态/声音项保持 `unavailable`，不以技术通过替代。修正复用下方既有最多两轮预算，不另设评分、付费工具或用户审批门槛。

## 批量制作前，用本片代表镜头预演

1. **选择能暴露问题的镜头。** 从本次正式计划选择最能验证画风与实现风险的镜头，例如开场大字与人物、真实资料展示、机制解释或复杂空间动作。常见任务可用少量镜头覆盖这些风险，数量随差异决定；复用已验证镜头时说明当前适用依据。
2. **先看构图。** 使用正式制作代码、实际字体与本期素材生成代表性阅读态，与原片及人物层合看。在常见手机观看尺度下先确认画面够亮、主体够大，再检查空间、中文排版、材质及已选参考的适用细节；暗部结构不清或核心动作偏小时，先调整光照/背景/材质、景别与版面，再扩展动画。
3. **再看连续动作。** 用同一代码和正式帧率生成该场必要短区间，在 `work/` 内按正常速度连续查看注意引导、主体变化、阅读态及前后交接；涉及工具处理、数据分发或结果汇聚时，覆盖其输入、变化、交接及结果，不只选最热闹的一瞬。涉及声音时按 UISFX 决策同段合听，检查速度曲线、物体接触、遮挡、清晰度和落稳；预览帧不能代替连续动态判断。
4. **明确可复用的结果。** 记录实际看到了什么、与参考的具体差距、修正及保留的代码/样式版本。代表镜头已解决明确问题后，才将其视觉和动作语言扩展到全片；不同制作路径仍分别验证必要能力。

预演是正式场景的制作中间态，源码和有效场景结果应进入后续制作与缓存；不另做无关示范片、整片测试成片或剪映测试工程。AI 自主观察和修正，用户未要求先审时不新增等待批准节点。它不代替最终正式文件的解码、合成、动态和声音检查，也不自动允许导入、上轨或导出。

预演发现的同一问题与正式检查共享既有最多两轮自动返修预算；不能按阶段重新计数。能力不足、明确问题仍未解决或需要扩大范围时，按总规则报告具体差距。用户后续主动提出的新反馈按原返修流程执行。

## 正式输出复查视觉完成度

在既有关键帧和连续动态检查中，先核对上述默认可见性要求，再判断：1）画面是否让本段的对象、变化或证据更容易理解；2）视觉主次、字体、色彩及材质是否与本期方向一致；3）重点是否有清楚可见的动作编排和结果，而普通段有适当阅读节奏；4）实际材质、边缘、接触、遮挡和声音是否暴露粗糙实现；5）相邻镜头的对象、画风和节奏是否接得上。无需为这些判断重新整片渲染或建立独立评分系统。

将设计与预演证据放入原制作计划/视觉参考记录，在现有 `checks.visual_references` 的 `design_rules`、`comparison` 和内容检查的 `finding/evidence` 中记录适用观察，无须新增装配 schema 或另造清单。观察须具体说明主体与内部动作是否可辨、分发/汇聚哪些路径和交接已看清；不适用项简述原因。偏暗、主体过小、处理变化不明显或路径/拼合难以追踪时记为 `issues`，按既有限返修流程修正后检查；未解决时保持未通过。仅因为不截字、动画能播放或技术核对通过，不能填成视觉完成度已通过。

`finalize_delivery.py` 核对文件与证据的一致性，不自动判断画面精致、科技风匹配或用户满意。报告保持“设计/预演已执行、正式输出检查状态、用户是否认可”的实际区别，具体审美效果以真实输出及用户反馈验证。
